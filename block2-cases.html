Когортный анализ: рекомендательная vs подписочная Лента

Пользователи, пришедшие через рекомендательную ленту (Discover), показывают выше D1 retention (42% vs 35%), но ниже D30 (8% vs 14%). Подписочные пользователи монетизируются лучше: ARPU × 1.7.

A/B-тест: редизайн рекомендаций

Контекст: новая ML-модель рекомендаций должна увеличить time spent на 3%+.

Проблема: network effects

Контент пользователя A показывается пользователю B. Если A в тесте и создаёт больше контента → B видит больше (даже если B в контроле). Это spillover-эффект: контрольная группа «загрязняется» эффектом теста.

Решение: cluster randomization

  • Группируем юзеров в кластеры по социальному графу (друзья → один кластер)
  • Сплиттинг по кластерам, а не по user_id
  • Внутри кластера все юзеры получают одну версию
  • Потеря: меньше effective sample size (кластеров меньше, чем юзеров)

MDE-расчёт

Базовый time spent = 32 мин/DAU, σ ≈ 45 мин. Хотим поймать +3% (≈ +0.96 мин).

n = (1.96 + 0.84)² × 2 × 45² / 0.96² ≈ 7.84 × 2 × 2025 / 0.9216 ≈ 34 400 юзеров на группу

С учётом cluster design (inflation factor ≈ 1.5 из-за внутрикластерной корреляции): n ≈ 51 600 на группу.

Экономика: +5% time spent → Ad Revenue

Модель:

ΔAd Revenue = DAU × ΔTime_Spent × Ad_Impressions_per_Minute × CPM / 1000

Подстановка:

  • DAU = 72M
  • ΔTime_Spent = +5% × 32 мин = +1.6 мин
  • Ad_Impressions_per_Minute = 0.8 (1 показ за ~75 сек в Ленте)
  • CPM = $4.2 (mix: feed ads + stories)
ΔAd Revenue/day = 72M × 1.6 × 0.8 × 4.2 / 1000 = $387 072

ΔAd Revenue/year ≈ $141M

Trade-off: больше time spent ≠ пропорционально больше ad revenue. При росте времени показы могут «размазаться» (frequency capping), CPM упасть из-за падения качества инвентаря. Реальный множитель — 0.6-0.8 от расчётного.

SQL: Rolling Retention для когорт Ленты

WITH cohort AS (
  SELECT
    user_id,
    MIN(DATE_TRUNC('day', timestamp)) AS cohort_date
  FROM feed_events
  WHERE event_name = 'feed_first_open'
    AND timestamp >= '2026-06-01'
  GROUP BY user_id
),
rolling AS (
  SELECT
    c.user_id,
    c.cohort_date,
    MAX(DATE_TRUNC('day', e.timestamp)) AS last_active_day,
    DATE_DIFF('day', c.cohort_date,
      MAX(DATE_TRUNC('day', e.timestamp))) AS last_day_n
  FROM cohort c
  JOIN feed_events e ON c.user_id = e.user_id
  GROUP BY c.user_id, c.cohort_date
)
SELECT
  cohort_date,
  COUNT(DISTINCT user_id) AS cohort_size,
  COUNT(DISTINCT CASE WHEN last_day_n >= 7 THEN user_id END)::FLOAT /
    COUNT(DISTINCT user_id) AS rolling_d7,
  COUNT(DISTINCT CASE WHEN last_day_n >= 30 THEN user_id END)::FLOAT /
    COUNT(DISTINCT user_id) AS rolling_d30
FROM rolling
GROUP BY cohort_date
ORDER BY cohort_date;

A/B-тест: кнопка «Написать автору»

Контекст: добавляем кнопку для написания сообщения автору клипа. Цель — увеличить engagement и viral loop.

Проблема: interference

Если сплиттить по зрителям (viewer_id): автор может получать сообщения от теста и контроля одновременно. Автор меняет поведение → эффект «размазывается».

Если сплиттить по авторам (creator_id): все зрители автора видят кнопку или не видят. Но авторы с кнопкой получают больше сообщений → могут начать создавать больше клипов → эффект на supply.

Решение: двухуровневый эксперимент

  1. Level 1 (creator-level): авторы рандомизированы на A/B. Измеряем: получили ли авторы больше сообщений, изменилось ли их поведение (creation rate)
  2. Level 2 (viewer-level within creator): среди зрителей авторов группы A — рандомизация по viewer_id. Измеряем: кликнули ли на кнопку, написали ли сообщение

Это позволяет разделить прямой эффект (зритель видит кнопку) и косвенный (автор получает фидбек → создаёт больше).

LTV автора клипов

Creator LTV = ARPU_from_views × Average_Creator_Lifetime

Подстановка:

  • Средний автор: 200 000 просмотров/мес, CPM = $3 → revenue = $600/мес
  • Average creator lifetime = 8 месяцев (churn rate = 12.5%/мес)
Creator LTV = $600 × 8 = $4 800

Приоритизация: фича для авторов (создание шаблонов, аналитика) оправдана, если стоимость разработки < creator_count × ΔLTV_per_creator. Для 50 000 активных авторов +10% LTV = 50 000 × $480 = $24M potential impact.

Growth Loops Клипов

K-factor:

  • Средний зритель шерит 0.3 клипа/день
  • Конверсия из шера в нового юзера = 8%
  • K = 0.3 × 0.08 = 0.024 — виральный эффект слабый

Но: есть content loop:

  • Авторы создают клипы → зрители смотрят → 3.2% зрителей становятся авторами → новый контент
  • Cycle time: ~7 дней (от первого просмотра до первой публикации)
  • Этот loop не показан в K-factor, потому что он не «приглашение», а «наблюдение → вдохновение → действие»

Усиление loops:

  • Viral loop: добавить «Share to friend» с превью → +0.05 к K-factor
  • Content loop: «Снять ответный клип» → сокращает cycle time с 7 до 2 дней → ускоряет loop в 3.5×
  • Paid loop: revenue от рекламы → reinvest в performance-маркетинг → +0.5M new users/мес

Клипы как двухсторонний маркетплейс

Supply (авторы) ↔ Demand (зрители). Cross-side network effect: больше авторов → больше контента → больше зрителей.

Chicken-and-egg решение:

  • Seed: привлечь 500 топ-авторов из других платформ (гарантии + финансовые бонусы)
  • Cross-promo: показывать клипы в Ленте ВК (demand-side bootstrap)
  • Guaranteed initial views: каждый новый клип получает 500+ просмотров (supply-side confidence)

Метрики:

  • Match Rate: 72% сессий заканчиваются 3+ досмотренными клипами → хорошая ликвидность
  • Fill Rate: 45% клипов получают ≥100 просмотров → умеренная, нужно больше demand
  • Density: 50K авторов / 50M зрителей = 1:1000 — дисбаланс, нужно больше авторов

A/B-тест: редизайн панели ввода

Контекст: новая панель ввода с быстрыми ответами и встроенным AI-ассистентом.

Гипотезы

  • H0: редизайн не влияет на messages sent per DAU
  • H1: редизайн увеличивает messages sent per DAU

Риск каннибализации

Быстрые ответы могут сократить количество отправленных сообщений: пользователь выбирает готовый ответ вместо того, чтобы написать 2-3 сообщения. Но при этом response_rate может вырасти.

Guard-метрика: avg message length. Если сообщения стали короче на 40%+ — коммуникация деградирует, даже если count вырос.

H1 должна быть двусторонней

Поскольку возможен эффект в обе стороны (быстрые ответы могут и увеличить, и уменьшить count), используем двустороннюю H1.

Экономика: indirect impact Мессенджера

Мессенджер сам по себе не генерирует значительный ad revenue. Но он — ключевой драйвер retention платформы: пользователь, активно переписывающийся, возвращается чаще и проводит больше времени в Ленте и Клипах.

Модель: counterfactual analysis

  • Группа A: пользователи с messages_sent > 10/день
  • Группа B: пользователи с messages_sent ≤ 10/день (matched по demographics)
  • Разница в DAU Ленты между A и B = +18%
  • Attributed ad revenue = ΔDAU × time_spent_per_DAU × impressions/min × CPM
Indirect Messenger Value = (DAU_A × time_A - DAU_B × time_B) × impr/min × CPM / 1000

Trade-off: correlation ≠ causation. Активные мессенджер-пользователи могут быть изначально более вовлечёнными. Для строгой оценки нужен инструментальный подход или эксперимент с ограничением функционала.

Network Effects Мессенджера

Same-side network effects: каждый новый пользователь увеличивает ценность для всех существующих (больше друзей в мессенджере → больше поводов зайти). K-factor:

  • Средний юзер приглашает 1.2 новых юзера за первые 30 дней
  • Конверсия приглашения → регистрация = 25%
  • K = 1.2 × 0.25 = 0.3 — умеренный органический рост

Усиление network loop:

  • «Ваши друзья в ВК» — автоматическая адресная книга (снижает friction приглашения)
  • Групповые чаты — каждый новый участник = ещё один человек, который тянет остальных
  • Стикеры и реакции — social currency, повод написать

Метрика network health: среднее количество контактов с 2+ сообщениями/неделю. Если <3 → риск оттока (нечего терять). Цель: ≥5 для новых юзеров к D14.

LTV платящего — SaaS-метод

LTV_SaaS = ARPU × (1 / Churn_Rate) × Gross_Margin
LTV_SaaS = $5.29 × (1 / 0.05) × 0.40 = $5.29 × 20 × 0.40 = $42.3

LTV бесплатного — через retention-кривую

Для ad-supported модели churn не имеет смысла (нет подписки), зато есть кривая retention:

LTV_retention = ARPU_per_day × Σ(Retention_Dt)

ARPU_per_day = $0.80 / 30 = $0.027. Сумма retention за 180 дней по измеренным точкам:

A/B-тест: Autoplay со звуком

Контекст: автовоспроизведение видео в Ленте со звуком (сейчас — без звука). Цель — увеличить watch time в Видео.

Целевые метрики

  • Goal: watch time per DAU (Видео) — ожидаемый рост +8%

Guard-метрики (cross-product)

  • Feed exit rate — если звук раздражает, пользователи уходят из Ленты
  • Feed session length — может упасть, если автовоспроизведение «ломает» скроллинг
  • Clips watch time — может вырасти (создаётся привычка к звуковому контенту) или упасть (каннибализация)

Дизайн

  • Сплиттинг по user_id (50/50)
  • Длительность: 2 недели (учесть weekend/weekday разницу в потреблении видео)
  • Ramp-up: 5% → 20% → 50%, проверка guard на каждом этапе

Pricing: подписка VK Видео

Модель: Freemium — бесплатный ad-supported + платная подписка $4.99/мес.

Ценовая эластичность: при повышении цены с $4.99 до $5.99 (+20%) отток подписчиков составил 8% → |elasticity| = 8/20 = 0.4 (неэластичный спрос). Вывод: можно поднимать цену — выручка вырастет.

Pricing experiment: нельзя A/B-тестить цену (юзеры видят разные цены). Альтернатива: тест на новом сегменте (новые регионы) или survey-based Van Westendorp. Результат: оптимальная цена для массового сегмента = $4.99, для premium = $7.99 (tiered pricing).
