# Стратегия развития групповых звонков в Максе

**Дата:** 2026-07-13
**Подход:** Capability-first (от стека к рынку)
**Статус:** Draft

---

## 1. Контекст

Групповые звонки в Максе уже запущены (SFU-архитектура, до 30-50 участников). B2B-направление — с нуля. Стратегия покрывает два параллельных стрима:

1. **B2C:** Рост использования групповых звонков среди физических лиц
2. **B2B:** Вход в сегмент командных звонков (замена Zoom, Контур.Толк, Telegram)

Оба стрима разделяют общую инфраструктуру, но имеют разные NSM, воронки и roadmap.

---

## 2. Capability Map

### 2.1. Имеется (готовые capability)

- **P2P и SFU-звонки** — 1-на-1 и групповые до 30-50 участников
- **VoIP Push** — мгновенная доставка входящих звонков (PushKit/FCM high-priority)
- **Signaling Server** — установка соединения, ICE/STUN/TURN
- **Opus codec** — аудио с адаптивным битрейтом
- **Мессенджер-база** — чаты, контакты, группы — контекст для звонков
- **Экосистема VK** — единый аккаунт, связность продуктов

### 2.2. Близко (1-2 квартала на существующей базе)

- **Simulcast** — multiple quality layers на SFU (критично для экономики при 10+ участников)
- **Экранное вещание (screen share)** — WebRTC API, клиентский UI + signaling
- **Запись звонков** — отдельный media-микросервис, записывающий потоки с SFU
- **Шифрование E2E для групп** — MLS-протокол, сложнее чем 1-на-1, но реализуемо

### 2.3. Далеко (2+ квартала, значительные инвестиции)

- **Интеграции с календарями** — Google Calendar, Outlook, OAuth, sync
- **Административная консоль** — управление пользователями, политиками, аудит
- **SSO/SAML** — корпоративная аутентификация
- **On-premise / Private Cloud** — развёртывание у клиента
- **Транскрипция и AI-фичи** — ASR, саммари, перевод, ML-стек

**Ключевой инсайт:** Разрыв между B2C и B2B — это преимущественно «далёкие» capability. Для роста B2C достаточно «близких». Для B2B-входа нужно минимум 2-3 из «далёких».

## 3. Стрим B2C: Рост групповых звонков

### 3.1. NSM и воронка

**NSM:** `group_calls_completed_per_DAU` — количество завершённых групповых звонков (2+ участника, >30 сек) на DAU

**Guard metrics:**
- `messenger_D7_retention` (звонки не ухудшают удержание мессенджера)
- `calls_infra_cost_per_user` (рост не обходится слишком дорого)
- `individual_call_completion_rate` (не каннибализируем 1-на-1)

**Воронка:**
Открыл Макс → Видит группу/чат → Нажал «Групповой звонок» → Кто-то присоединился → Звонок состоялся (2+ участника, >30 сек) → Повторный звонок

### 3.2. Гипотезы роста

#### H1: Снижение трения при инициации (ICE: 576)

**Проблема:** Пользователи не знают о групповых звонках или путь к ним слишком длинный.

**Решения:**
- Один тап из группового чата — видимый CTA
- Виджеты на главном экране мессенджера — активные звонки групп
- Scheduled group calls — запланировать звонок в группе с напоминанием (как в Telegram voice chat)

**Метрики:** `group_call_initiation_rate`, `group_call_discovery_rate`

#### H2: Снижение порога присоединения (ICE: 441)

**Проблема:** Люди видят, что идёт звонок, но не присоединяются — барьер входа высок.

**Решения:**
- Звонок как «комната» — можно войти/выйти без окончания для всех
- Push-уведомление «Идёт звонок в группе X» с кнопкой «Присоединиться»
- Аудио-only по умолчанию (меньше барьер, чем видео)
- Предпросмотр — кто уже в звонке, перед тем как зайти

**Метрики:** `group_call_join_rate`, `group_call_participants_avg`

#### H3: Новые сценарии использования (ICE: 210)

**Проблема:** Групповые звонки ассоциируются только с «договориться о встрече» — нужно расширить use cases.

**Решения:**
- Drop-in audio rooms (voice rooms) — зайти на огонёк, без формата встречи
- Семейные звонки, студенческие группы, игровые сессии
- Интеграция с VK Clips/Feed — «обсудить вместе» после просмотра

**Метрики:** `new_user_segments_in_group_calls`, `group_call_frequency_per_user`

#### H4: Качество и масштаб (ICE: 240)

**Проблема:** При 10+ участниках качество падает, трафик растёт, опыт ухудшается.

**Решения:**
- Simulcast — SFU отправляет каждому участнику качество, соответствующее его каналу
- Адаптивная раскладка видео (speaker view ↔ grid, автоматическое переключение)
- Фоновый режим — слушать звонок, пока в другом приложении
- Audio-only для «молчащих» участников (не отправлять видео-поток)

**Метрики:** `MOS_group_call`, `group_call_drop_rate`, `infra_cost_per_group_call_min`

#### H5: Социальный / viral эффект (ICE: 216)

**Проблема:** Групповые звонки — сетевой продукт: ценность растёт с числом участников, но нет механизмов viral loop.

**Решения:**
- Приглашение не-пользователей Макса в звонок (ссылка → web-клиент → конверсия в приложение)
- Шеринг Moments/Clips из звонка (скриншот, короткий клип) → привлекает новых пользователей
- Реферальная механика: «приведи 3 друзей в групповой звонок — получи стикерпак»

**Метрики:** `group_call_invite_non_user_rate`, `web_to_app_conversion_from_call`, `viral_coefficient_group_calls`

**Что исследуем:** Работает ли вирусный цикл через внешних пользователей? Какова конверсия ссылка→звонок→установка?

#### H6: Кросс-продуктная интеграция с VK (ICE: 189)

**Проблема:** Макс существует в экосистеме VK, но звонки изолированы от других продуктов.

**Решения:**
- «Обсудить в звонке» из VK Clips/Feed/Дзен — один тап, создаётся мгновенный групповой звонок
- Совместный просмотр (watch party) — синхронный просмотр контента + аудио-комментарии
- Звонок из VK Почты / Документов — «позвонить автору документа»

**Метрики:** `cross_product_call_initiation_rate`, `calls_from_external_entry_points`, `retention_cross_product_users_vs_pure`

**Что исследуем:** Какой процент звонков может генерироваться извне Макса? Влияет ли кросс-продуктовый вход на retention?

#### H7: Гибридные форматы общения (ICE: 168)

**Проблема:** Групповой звонок — это «всё или ничего»: или ты в звонке, или в чате. Нет промежуточных форматов.

**Решения:**
- Чат внутри звонка (текст + реакции параллельно аудио) — для тех, кто не может говорить
- Асинхронный голос — оставить голосовое сообщение в групповом звонке, другие послушают позже
- «Подними руку» — подать сигнал, что хочешь говорить, модератор даёт слово

**Метрики:** `in_call_message_rate`, `async_voice_message_in_group_rate`, `raise_hand_usage_rate`

**Что исследуем:** Увеличивает ли чат внутри звонка продолжительность? Снижает ли «подними руку» барьер входа для интровертов?

#### H8: Персонализация и привыкание (ICE: 126)

**Проблема:** Нет механизмов формирования привычки — групповые звонки не становятся ритуалом.

**Решения:**
- Регулярные звонки (standup, утренний кофе) — автоматическое расписание с напоминаниями
- Custom звонки — стикеры, фоны, звуки уведомлений для конкретной группы
- Streak-механика — счётчик последовательных дней с групповым звонком в группе

**Метрики:** `recurring_group_call_rate`, `habitual_call_D7_retention`, `streak_completion_rate`

**Что исследуем:** Формируют ли запланированные звонки привычку? Какой процент повторных звонков — scheduled vs ad-hoc?

### 3.4. Фазы B2C

**Q1: Быстрые победы — H1 + H2**
- Один тап для инициации группового звонка из чата
- Push-уведомления о текущих звонках с кнопкой «Присоединиться»
- Предпросмотр участников перед входом
- Целевая метрика: `group_calls_completed_per_DAU` +30% за квартал

**Q2: Качество при масштабе — H4**
- Simulcast на SFU (общая инфра с B2B)
- Адаптивная раскладка видео
- Фоновый режим (audio-only в фоне)
- Целевая метрика: `MOS_group_call` ≥ 4.0, `group_call_participants_avg` +20%

**Q3: Новые сценарии — H3**
- Voice rooms / drop-in audio
- Интеграция с VK-контентом
- Scheduled group calls с напоминаниями
- Целевая метрика: новые сегменты пользователей в групповых звонках +15%

## 4. Стрим B2B: Вход в сегмент командных звонков

### 4.1. Проблема

Компании в РФ используют для созвонов Zoom (доступ ограничен), Контур.Толк, Яндекс.Телемост, Telegram, Сферум. Нет единого «российского Zoom» с интеграцией в мессенджер и корпоративную экосистему. Макс может занять эту нишу.

### 4.2. Конкурентный ландшафт

| Конкурент | Сильные стороны | Слабые стороны |
|-----------|----------------|----------------|
| **Zoom** | Функциональность, привычка | Ограниченный доступ в РФ, цена, нет мессенджера |
| **Telegram** | База, голосовые чаты | Ограниченный screen share, нет записи, несерьёзно для бизнеса |
| **Контур.Толк** | Интеграция с Контур.Эльба/Бухгалтерия | Узкая база, слабый мессенджер |
| **Яндекс.Телемост** | Интеграция с Яндекс 360 | Слабый мессенджер, малая база мобильных пользователей |
| **Сферум** | Гос. сегмент, 152-ФЗ | Узкий сегмент, слабый UX |

**White space:** Мессенджер + командные звонки + российская инфраструктура + бесплатный вход для малых команд.

### 4.3. Сегментация

| Сегмент | Размер | Боль | Готовность платить | Сложность входа | Приоритет |
|---------|--------|------|---------------------|-----------------|-----------|
| **Малый бизнес** (5-50) | Большой | Telegram/WhatsApp — несерьёзно, Zoom — дорого/недоступно | Низкая (free → freemium) | Низкая | **P0** |
| **Средний бизнес** (50-500) | Средний | Нет интеграции мессенджер+звонки+документы | Средняя (per-seat) | Средняя | P1 |
| **Enterprise** (500+) | Малый | 152-ФЗ, on-prem, SSO, аудит | Высокая (enterprise license) | Высокая | P2 |

### 4.4. Точка входа: Малый бизнес

**Почему малый бизнес:**
- Низкий порог — сотрудники уже используют Макс лично
- Минимум «далёких» capability (нет SSO, нет on-prem)
- Быстрая валидация product-market fit
- Viral loop: сотрудники → компании → компании → сотрудники

### 4.5. Ценностное предложение

**«Мессенджер с командными звонками — всё в одном, без Zoom»**

Ключевые дифференциаторы:
1. **Мессенджер + звонки без переключения** — Zoom только звонки, Telegram ограниченные звонки
2. **Бесплатно для малых команд** — freemium до 10 участников / 40 мин (как Zoom-free, но с мессенджером)
3. **Российская инфраструктура** — данные в РФ, соответствие 152-ФЗ

### 4.6. MVP для B2B (малый бизнес)

**Входит:**
- Групповые звонки до 10 участников
- Экранное вещание (screen share)
- Ссылка на звонок (отправил ссылку — не нужно быть в контактах)
- Повестка/заметки в чате во время звонка
- Запись звонка (в облако, 30 дней хранения)
- Workspace для команды (отдельное пространство от личных чатов: список участников, общие звонки, история записей; администратор workspace может управлять участниками)

**Не входит в MVP:**
- SSO/SAML, admin console, on-prem, calendar integrations, AI-фичи

### 4.7. Метрики B2B

**NSM:** `b2b_teams_active_weekly` — команды с 3+ групповыми звонками/неделю

**Воронка активации:**
Создал workspace → Пригласил 3+ коллег → Первый групповой звонок → 3 звонка за неделю → Active team

**Guard metrics:**
- `infra_cost_per_b2b_user` — B2B не обходится дороже чем приносит
- `b2c_experience_quality` (MOS, latency) — B2B-трафик не ухудшает B2C

**Revenue proxy (после запуска монетизации):** `seats_on_paid_plan`

### 4.8. Гипотезы B2B

#### BH1: Bottom-up adoption — сотрудники тянут продукт в компанию (ICE: 378)

**Гипотеза:** Люди, использующие Макс для личных звонков, начнут использовать его для рабочих, если убрать барьер (workspace, отделение от личного).

**Что исследуем:**
- Какой процент групповых звонков в Максе уже сейчас — рабочие? (анализ по времени дня: 9-18 vs вечер)
- Готовы ли пользователи установить «рабочий» Макс рядом с личным? Или хотят всё в одном?
- Какова конверсия: личный пользователь → создал workspace → активная команда?

**Валидация:** CustDev с 20 владельцами малого бизнеса, уже использующими Макс лично. A/B тест: показать CTA «Создать workspace» пользователям с групповыми звонками в рабочие часы.

#### BH2: Мессенджер + звонки — реальный якорь или иллюзия? (ICE: 336)

**Гипотеза:** Компании ценят мессенджер+звонки в одном продукте больше, чем отдельные инструменты.

**Что исследуем:**
- Сколько инструментов для коммуникации использует типичная компания 10-50 человек? (ожидаем: 3-5 — мессенджер, почта, Zoom, телефония)
- Каков реальный pain от переключения между мессенджером и звонками?
- Консолидация — это реальный мотиватор покупки или «nice to have»?

**Валидация:** Опрос 50 компаний малого бизнеса. Конджоинт-анализ: мессенджер+звонки vs только звонки (Zoom) vs только мессенджер (Telegram). Цена willingness-to-pay для каждого варианта.

#### BH3: 152-ФЗ и российская инфраструктура — драйвер или гигиенический фактор? (ICE: 280)

**Гипотеза:** Соответствие 152-ФЗ и хранение данных в РФ — критичный фактор выбора для компаний с гос. контрактами, но не для малого бизнеса.

**Что исследуем:**
- Какой процент малого бизнеса обязан хранить данные в РФ? (ожидаем: 10-20% — гос. контракты)
- Для остального малого бизнеса — это фактор выбора или «и так норм»?
- На каком этапе роста компании 152-ФЗ становится актуальным?

**Валидация:** Сегментный анализ. CustDev с двумя группами: компании с гос. контрактами и без. Измерить willingness-to-pay premium за «российскую инфраструктуру».

#### BH4: Freemium-лимиты — где порог конверсии? (ICE: 315)

**Гипотеза:** Лимиты «10 участников / 40 мин» достаточны для активации, но достаточны для конверсии в paid? Возможно, оптимальные лимиты другие.

**Что исследуем:**
- Средний размер командного звонка у малого бизнеса (ожидаем: 3-6 человек)
- Средняя длительность (ожидаем: 15-45 мин — 40 мин может быть слишком щедро)
- На каком лимите длительности пользователи чаще всего упираются?
- Что сильнее драйвит конверсию: лимит участников или лимит длительности?

**Валидация:** A/B тест с разными лимитами: (10/40) vs (8/30) vs (12/60). Измерить активацию + конверсию в paid для каждой группы.

#### BH5: Telegram — главный конкурент или нецелевой? (ICE: 252)

**Гипотеза:** Telegram — де-факто стандарт для малых команд в РФ, но его звонки воспринимаются как «несерьёзные». Макс может позиционироваться как «Telegram, но для бизнеса».

**Что исследуем:**
- Какой процент малого бизнеса использует Telegram для рабочих звонков?
- Что именно делает Telegram-звонки «несерьёзными»? (UX? нет записи? нет screen share? имидж?)
- Если Макс будет функционально эквивалентен Telegram + добавить бизнес-фичи — это достаточный reason to switch?
- Или привычка и база контактов в Telegram — непреодолимый барьер?

**Валидация:** CustDev с 30 компаниями, использующими Telegram для рабочих звонков. Анализ switching cost: что нужно, чтобы перенести команду в другой мессенджер?

#### BH6: Экосистемный lock-in через VK-продукты (ICE: 168)

**Гипотеза:** Интеграция Макса с другими VK-продуктами (документы, почта, облако) создаёт lock-in, который удерживает компании от оттока.

**Что исследуем:**
- Какие VK-продукты уже используются целевыми компаниями? (VK почта? VK Work? Облако?)
- Насколько глубокой должна быть интеграция, чтобы создать lock-in? (простая ссылка vs shared storage vs единый поиск)
- Существует ли «экосистемный溢价» — готовы ли компании платить больше за интеграцию?

**Валидация:** Корреляционный анализ: retention команд, использующих 1 vs 2 vs 3+ VK-продуктов. CustDev: что было бы критичной интеграцией?

#### BH7: Запись и заметки — killer feature или table stakes? (ICE: 224)

**Гипотеза:** Запись звонка — одна из самых запрашиваемых B2B-фич, но это может быть «мотиватор покупки» (люди платят за это) или «гигиенический фактор» (все ожидают это бесплатно).

**Что исследуем:**
- Какой процент компаний записывает звонки? (ожидаем: 30-50% для встреч, 80%+ для интервью)
- Готовы ли платить за запись отдельно или только в составе пакета?
- Что важнее: запись видео/аудио или автоматический протокол (AI-саммари)?
- Конкурентный бенчмарк: кто предоставляет запись бесплатно?

**Валидация:** A/B тест: включить запись бесплатно (с водяным знаком) vs только в paid. Измерить влияние на активацию + конверсию.

#### BH8: Ссылка-приглашение — сеть расширяется за пределы Макса (ICE: 294)

**Гипотеза:** Возможность позвонить по ссылке человеку без Макса (web-клиент) — критична для B2B, потому что не все контрагенты установят приложение.

**Что исследуем:**
- Как часто в рабочих звонках участвуют внешние контрагенты (не из команды)?
- Каков процент звонков, где хотя бы 1 участник — не пользователь Макса?
- Конверсия web → app: сколько внешних участников после звонка устанавливают Макс?
- Качество web-клиента: достаточно ли WebRTC в браузере для приемлемого опыта?

**Валидация:** Эксперимент: запустить web-клиент для входа по ссылке. Измерить: конверсия ссылка→вход, качество MOS web vs native, web→app conversion rate.

### 5.2. Принцип разделения инфраструктуры

- **SFU общий** — один кластер, разные приоритеты трафика (B2B-запись имеет более высокий приоритет, но не блокирует B2C)
- **Separate signaling for B2B** — ссылка-приглашение требует другого signaling path (внешние пользователи, не в контактах)
- **Recording pipeline** — отдельный микросервис, потребляет потоки с SFU, не влияет на live-трафик
- **Guard: B2C quality first** — если B2B-трафик начинает ухудшать B2C-опыт, throttling B2B

|------|-------------|---------|-----------|

| Отсутствие чёткого конкурентного преимущества B2B | Высокая | Высокое | Валидация через эксперименты Q1: измерить willingness-to-pay, определить real differentiator |

## 8. Ключевые решения, требующие валидации

1. **Какой real differentiator для B2B?** Мессенджер+звонки — гипотеза, нужно подтвердить через CustDev с малым бизнесом
2. **Готовность платить?** Freemium с конверсией 10% — предположение, нужно проверить через A/B тестирование лимитов
3. **Viral loop B2C→B2B?** Работает ли перенос из личного в рабочее? Нужен эксперимент с workspace-CTA
4. **Раздельная или общая инфра?** Если B2B-трафик не влияет на B2C — общий SFU. Если влияет — раздельные кластеры
5. **Приоритет screen share vs. ссылка-приглашение?** Оба P0, но если ресурс ограничен — ссылка-приглашение даёт больший охват (люди могут звонить внешним)
